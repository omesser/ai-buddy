Launcher Unhealthy State

Before each attach, fidget probes the launcher with a version check under a short timeout. Three outcomes: not found, unhealthy, or healthy. The unhealthy state is new.

Three probe outcomes

Not Found

Binary not on PATH. Existing landing (#1105).

Unhealthy

Present but broken: nonzero exit, no output, or timeout. New sticky state.

Healthy

Version check passed. Attach as today.

Settings state

npx preset (claude, codex, pi)
claude is unhealthy: `npx --version` exited with exit status: 1. Run npx --version in a terminal to check what is wrong. The AI runs on static weights until it is fixed; Model API above hands the HTTP endpoint back.
First-party CLI (copilot, goose, hermes)
hermes is unhealthy: `hermes --version` timed out after 3.0s. Run hermes --version in a terminal to check what is wrong. The AI runs on static weights until it is fixed; Model API above hands the HTTP endpoint back.
Broken Node.js
codex is unhealthy: `npx --version` produced no output. Run npx --version in a terminal to check what is wrong. The AI runs on static weights until it is fixed; Model API above hands the HTTP endpoint back.

Chat surface state

Chat landing (same as Settings)
The launcher is unhealthy. The sentence names the command and shows abbreviated output. The ways out: pick another Harness, switch to Model API, or turn AI off. Same exit paths as the missing-launcher landing (#1105).

Verification

Each preset documents its probe command. npx presets (claude, codex, pi) probe npx --version. First-party CLIs probe their own binary with --version. antigravity probes agy_acp_server.par --help (or .exe on Windows).

Tests drive fixture launchers that exit nonzero, hang, or produce no output. Each outcome reaches its documented state.

Open decisions

None. The design matches the acceptance criteria from the issue.
