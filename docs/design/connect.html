One unified landing page

All three Chat empty situations (not configured, switched off, needs login) share the same landing page structure. The heading and lede adjust, but the four connect buttons and the Settings control stay the same. This is the product's default posture: steer toward Harness landing, not HTTP-first copy.

When the user has chosen HTTP Completer mode in Settings (not Harness landing), Chat does not show the Harness landing buttons. HTTP Completer is a separate mode. The default empty states above assume Harness mode or no configured Completer at all.

Needs login variant

When the attached Harness answers session/new with ACP -32000 (auth required), the lede becomes "{Harness} needs login, or you can switch to…" followed by the same four buttons. The command is shown for those who prefer their own terminal. Clicking a button spawns the Harness's own login (ADR-0010: ai-buddy never collects a credential).

Four main Harnesses

Claude Code (via Zed's adapter), Codex, Grok, and OpenCode are the four tiles. Each gets a simple icon (marks are trademarks; wordmarks in our own type are the safe default). Hermes is reachable through "More options in Settings" but not a primary tile.

Connect behavior

Clicking a button spawns the Harness's login command detached (claude /login, codex login, grok login, opencode login). No credentials collected, no auto-approve. "More options in Settings" opens Settings focused on the Completer/Harness row if practical.

Out of scope

Holding credentials (#371), auto-approve flags (ADR-0017), and which Harnesses exist (#457, #458) are all out of scope. A connect button starts the Harness's own login; it never collects, stores, or proxies a secret.
